# InkBridge 서재 서버

맥 폴더의 HTML·PDF·PowerPoint·Word 문서를 iPad에서 보고 Apple Pencil로 필기하게 해 주는 로컬 웹 서버입니다. InkBridge Pad의 **서재**가 이 서버의 문서를 책장으로 보여 주고, iPad Safari로도 열 수 있습니다. 필기는 작업 폴더의 `.pencil-review/`에 저장되고, 맥에서는 iPad와 같은 크기의 iframe으로 겹쳐 보며, Claude가 읽을 수 있는 요약으로 내보냅니다.

InkBridge의 다른 두 버전(맥 화면·Sidecar판)과는 필기 파일 형식이 다릅니다. 이 도구의 옛 이름은 Pencil Review였고, 호환을 위해 데이터 폴더(`.pencil-review/`)·쿠키·웹 API 이름(`__pr`, `__pencilReview`)에 그 이름이 남아 있습니다. 설계 결정과 근거는 [DESIGN.md](DESIGN.md)에 있습니다.

## 실행

Node 24(fnm)만 있으면 됩니다. 외부 패키지는 쓰지 않습니다.

```sh
node library/server.mjs <작업 폴더> --port 5173
```

- 서버가 `http://<맥 이름>.local:5173/?t=<토큰>` 형태의 **iPad 권장 주소**를 출력합니다. iPad에서는 이 주소 하나만 계속 쓰세요. 필기 대기열과 접속 쿠키는 주소(호스트명·포트)별로 따로 저장되므로, IP 주소로 열면 `.local` 주소에서 보내지 못한 필기가 보이지 않습니다.
- 토큰이 붙은 주소로 한 번 열면 쿠키가 저장되고 주소창에서 토큰이 사라집니다. 토큰은 `.pencil-review/token`에 남아 서버를 다시 켜도 같습니다. 바꾸려면 `--new-token`.
- 처음 실행할 때 macOS 방화벽이 묻는다면 Node의 수신 연결을 허용합니다.
- HTML은 서버 주소로 여세요. `file://`·AirDrop·파일 앱으로 열면 필기 레이어가 없습니다.
- 작업 폴더가 git 저장소라면 `.pencil-review/`를 `.gitignore`에 넣으세요.

## 쓰는 법

- **홈 화면**: 서버 주소(`http://<맥 이름>.local:5173/`)를 열면 폴더 안 HTML 문서 목록이 최근 수정 순으로 나옵니다. 문서마다 지금까지 쓴 필기 수가 표시되고, 파일이 바뀌거나 필기가 생기면 목록이 저절로 갱신됩니다. 필기 보기(맥 뷰어)와 입력 실험도 여기서 엽니다. 문서 안 도구 막대의 ‘홈’으로 돌아옵니다. 폴더의 `index.html`은 `/index.html`로 엽니다.
- **iPad**: Pencil로 쓰고, 손가락으로 스크롤·확대합니다. 오른쪽 아래 도구 막대에서 펜·형광펜·지우개(획 단위), 색 5개, 굵기 2단계, 실행 취소·다시 실행, 숨기기, 전체 지우기를 고릅니다. 상태 표시는 `viewport 크기 · 획 수 · 전송 대기 · 오프라인`입니다.
- **리뷰 단위**: (페이지, 콘텐츠 버전, viewport 크기)마다 리뷰가 하나입니다. HTML·CSS를 고치면 iPad 화면은 펜을 뗀 뒤 쉬는 순간(0.8초)에 새로고침되고, 새 버전의 빈 리뷰가 시작됩니다. 이전 필기는 이전 버전의 스냅숏과 함께 보존됩니다. 회전·Split View로 크기가 바뀌어도 다른 리뷰로 바뀝니다.
- **앱처럼 열기**: iPad Safari에서 홈 화면을 연 뒤 공유 메뉴 → ‘홈 화면에 추가’를 누르면 Safari 주소창 없이 전체 화면 앱처럼 열립니다(상단 시계·배터리 표시줄은 남음). 홈 화면 앱은 Safari와 저장 공간·쿠키가 따로라서 처음 한 번은 아이콘 안의 토큰 주소로 자동 로그인합니다. 맥에서는 Safari의 파일 → ‘Dock에 추가’나 Chrome의 ‘앱 설치’로 같은 방식을 쓸 수 있습니다.
- **도구 막대**: 한 줄짜리 막대에 펜·형광펜·지우개, 색 5개, 굵기 3단계(글자 대신 현재 색의 선 굵기로 표시), 실행 취소·다시 실행, ⋯ 메뉴가 있습니다. 오른쪽 끝 버튼은 지금 도구를 그 색으로 보여 주며, 짧게 누르면 막대가 그 자리로 접히고 잡고 끌면 막대가 옮겨집니다(놓은 곳에서 가까운 모서리에 붙어 화면 가운데 쪽으로 펼쳐짐). 위치와 접힘은 기기에 기억됩니다. 터치가 없는 기기(맥)에서는 막대가 나오지 않고 필기만 보이며, 맥·Sidecar에서 쓰려면 주소 끝에 `?tools=1`을 붙입니다.
- **⋯ 메뉴**: 연결 상태·전송 대기, 문서 목록, 필기 숨기기, 마우스로 그리기, 저장(이 페이지 / 이 문서 전체), 지우기(이 페이지 / 이 문서 전부). 전송 대기나 연결 문제가 있으면 ⋯에 점이 표시됩니다.
- **저장과 삭제**: ‘페이지’는 단계·쪽 하나(`#step=3`, `#page=5`)이고 ‘문서’는 그 파일 전체(모든 페이지·화면 크기·이전 버전)입니다. 저장하면 맥의 `.pencil-review/saved/<문서>/<시각>[-page]/`에 리뷰별 `REVIEW.md`·`review.json`·`strokes.svg`가 생깁니다. 페이지 지우기는 실행 취소할 수 있고, 문서 전부 지우기는 확인 후 되돌릴 수 없습니다. 필기는 원래 자동 저장되며, ‘저장’은 그 시점의 사본을 남기는 기능입니다.
- **변환 문서는 맥·iPad가 같은 필기**: PDF·PowerPoint·Word 문서의 필기는 화면이 아니라 쪽 기준 좌표로 저장되어, iPad 가로·세로, 맥 브라우저(`?tools=1`), 맥 뷰어가 모두 같은 필기를 보고 실시간으로 함께 고칩니다. HTML 문서는 화면 크기마다 글자 배치가 달라 지금처럼 화면 크기별 리뷰입니다. 이 방식 이전에 쓴 변환 문서 필기는 맥 뷰어와 PDF 내보내기에는 나오지만, 문서를 열었을 때는 보이지 않습니다.
- **PDF로 내보내기 (필기 포함)**: PDF·PowerPoint·Word 문서에서 ⋯ 메뉴(앱에서는 도구 막대의 ⋯, 맥 뷰어에서는 위쪽 버튼)에 나옵니다. 원본 PDF(PowerPoint·Word는 변환 때 Keynote·Pages가 만든 `converted/<파일>/source.pdf`) 위에 현재 버전의 필기를 모든 쪽·화면 크기에서 그려 새 PDF를 만들고, 원본은 바꾸지 않습니다. 원본 쪽은 벡터 그대로라 글자 선택·검색이 됩니다. 앱에서는 공유 시트(파일에 저장·AirDrop)로, 브라우저에서는 다운로드로 받고, 맥에도 `.pencil-review/saved/<문서>/<시각> <이름> (필기).pdf` 사본이 남습니다. 쪽 밖 여백에 쓴 필기와 원본 PDF의 링크·주석은 들어가지 않습니다. textutil로 바뀐 Word 문서와 HTML 문서는 아직 지원하지 않습니다. 코드는 `lib/pdf-ink.mjs`, `scripts/pdf-ink.swift`.
- **Pencil 더블탭·스퀴즈**: Safari·Chrome에는 이 신호가 오지 않아 아래 **iPad 앱**에서만 동작합니다(앱의 지우개 전환·펜 끝 팔레트).
- **따라가기**: 홈의 ‘필기 보기’(`/__pr/view?follow=1`)는 iPad가 지금 보는 문서·화면 방향·페이지를 따라갑니다. 필기하지 않고 페이지만 넘겨도 따라갑니다(iPad가 15초마다, 그리고 페이지를 넘길 때마다 위치를 알림).
- **페이지 동기화**: 뷰어 위쪽의 ‘페이지 동기화’를 켜면 맥에서 넘긴 페이지(뷰어 안의 버튼·화살표 키)로 iPad도 넘어갑니다. iPad가 같은 문서를 열고 있을 때만 적용됩니다.
- **다른 문서 가져오기**: HTML은 폴더에 넣기만 하면 홈에 나옵니다. PDF, PowerPoint(.pptx·.ppt), Keynote(.key), Word(.docx·.doc·.rtf·.odt), Pages(.pages)는 폴더에 넣으면 서버가 자동으로 `converted/<파일 경로>/index.html`로 바꿉니다. PDF는 쪽마다 이미지로 그려 한 화면에 한 쪽씩 보여 주며(‹ ›, 화살표 키, 손가락 좌우 쓸기), PowerPoint·Keynote는 Keynote로, Word·Pages는 Pages로 PDF를 만든 뒤 같은 방식으로 바꿉니다. 처음 한 번 macOS가 Keynote·Pages 제어 권한을 묻습니다. Pages가 안 되면 Word 계열은 `textutil`로 HTML로 바꿉니다(레이아웃은 단순해짐). Google Docs는 PDF나 Word로 내려받아 넣으세요. 파일을 고치면 다시 변환되고, 변환 중·실패는 홈에 표시됩니다.
- **맥에서 보기**: `http://localhost:5173/__pr/view`에서 리뷰를 고르면, 필기할 때의 크기·버전 그대로 iframe에 표시됩니다. 창이 좁으면 레이아웃은 그대로 두고 그림만 축소합니다. iPad에서 그리는 중인 선이 펜을 떼기 전부터 따라 그려지고, 펜을 떼면 저장된 획으로 바뀝니다. 지우기·실행 취소도 바뀐 획만 받아 반영합니다.
- **Claude에게 넘기기**: 뷰어의 ‘내보내기’를 누르면 `.pencil-review/exports/<리뷰 ID>/`에 `REVIEW.md`(획마다 위치·아래 요소의 선택자·텍스트·주변 문장), `review.json`, `strokes.svg`가 생깁니다. 해당 버전 원본은 `.pencil-review/snapshots/<버전>/`에 있습니다. "이 리뷰 반영해 줘"와 함께 `REVIEW.md` 경로를 알려 주면 됩니다.
- **동적 페이지(단계·탭)**: 페이지가 현재 상태를 주소의 `#` 뒤에 적어 두면(예: `#step=3`) 필기도 그 상태에 붙습니다. 3단계에 쓴 필기는 3단계 화면에서만 보입니다. 맥 뷰어에서는 위쪽 상태 목록으로 필기가 있는 단계로 이동합니다. 상태를 주소에 남기지 않는 페이지는 모든 필기가 한 화면에 겹쳐 보이고, 슬라이더 값처럼 주소에 없는 상태는 구분하지 않습니다. 예제: `examples/lesson.html`.
- **펜으로 누르기**: 버튼·링크·접힌 설명 위를 펜으로 짧게 톡 치면 눌립니다. 끌면 필기입니다. 슬라이더는 펜으로 끌어도 필기가 되지 않고 값이 움직입니다.
- **맥·Sidecar에서 쓰기**: `?tools=1`로 연 뒤 도구 막대의 ‘마우스로 그리기’를 켜면 마우스/펜 드래그가 필기가 됩니다.
- **입력 실험**: `/__pen-test`에서 Pencil·손가락·손바닥 입력, 링크 위 필기, 확대·회전 후 좌표를 확인하고 ‘결과 저장’을 누르면 `.pencil-review/pen-tests/`에 기록됩니다.

## iPad 앱 (InkBridge Pad의 서재)

InkBridge Pad의 **서재**는 이 서버의 `GET /__pr/api/pages`(책 종류·표지·쪽 수 포함)와 `GET /__pr/api/conversions`(변환 중인 문서)로 책장을 그립니다. **가져오기**는 iPad 파일을 `POST /__pr/api/import?name=<파일 이름>`으로 올리며, 서버는 작업 폴더의 `imported/`에 같은 이름이 있으면 `이름 (2).pdf`처럼 바꿔 저장합니다(PDF·PowerPoint·Keynote·Word·Pages, 최대 300MB). HTML은 이 서버와 같은 출처에서 스크립트가 실행되므로 가져오기로 받지 않고, 맥 사용자가 폴더에 직접 넣은 것만 엽니다. 책을 펼치면 같은 페이지가 상태 표시줄 없이 전체 화면으로 열립니다. 이때는 이 웹 도구 막대가 나오지 않고 앱의 도구 막대(맥 화면 모드와 같은 유리 도구 막대·펜 종류·스퀴즈 팔레트)가 페이지의 필기를 조작합니다. 페이지는 `window.webkit.messageHandlers.pencilReview`가 있으면 앱 안이라고 보고 `__pencilReview.setInk({ tool, color, width, kind, finger })`·`__pencilReview.command(name)`을 받으며, 실행 취소 가능 여부·연결 상태를 앱에 보냅니다. 펜 종류(`kind`: gel·ballpoint·fountain)는 획에 저장되고 웹에서도 그 모양으로 그립니다. 필기 저장·실시간 전송·따라가기는 웹과 같습니다. 앱 코드는 `../iPad/LibraryView.swift`(책장), `../iPad/DocumentViews.swift`, `../iPad/WebViewController.swift`이며 빌드·설치와 모드 전환은 [../README.md](../README.md)에 있습니다.

- 처음 열면 서버 주소를 묻습니다. 서버가 출력한 `…?t=토큰` 주소를 붙여넣습니다. 책을 펼친 상태에서 세 손가락으로 0.8초 누르면 새로고침·서버 주소 바꾸기·서재로 메뉴가 나옵니다.
- 앱은 Safari와 저장 공간이 따로라서 Safari에서 보내지 못한 필기는 Safari에서 열어야 전송됩니다.

## 끊김과 저장

획은 먼저 브라우저의 IndexedDB에 저장한 뒤 서버로 보내고, 서버가 받았다고 응답한 다음에 지웁니다. 와이파이가 끊겨도 **이미 열려 있는 페이지**에서는 계속 쓸 수 있고, 다시 연결되거나 같은 주소로 페이지를 다시 열면 전송됩니다. 끊긴 상태에서 새로고침하거나 Safari를 다시 열면 페이지가 열리지 않습니다(HTTP 주소에서는 서비스 워커를 쓸 수 없음). 서버는 같은 작업을 두 번 받아도 한 번만 반영하고, 파일은 임시 파일을 쓴 뒤 교체합니다.

## 지원 범위

정적 HTML의 일반 문서 흐름을 대상으로 합니다. fixed/sticky 요소, 내부 스크롤 영역, transform으로 움직이는 내용, iframe 내부, SPA·개발 서버, CSP로 외부 스크립트를 막는 페이지는 위치를 보장하지 않습니다. 같은 viewport여도 Safari와 맥 브라우저의 글꼴·렌더링 차이는 남습니다.
